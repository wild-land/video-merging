# EasyNVR 录像合并（飞牛 fnOS 原生应用）

这个项目现在提供 **fpk 原生应用安装包**，安装和运行不需要 Docker。应用扫描 EasyNVR 的 `设备/通道/YYYYMMDD` 日期目录，每 60 段（可配置）合并成一个 MP4，最后不足一组的片段也会合并。只处理今天以前的日期目录，原片保留。输出形如 `YYYYMMDD/Video1.mp4`、`YYYYMMDD/Video2.mp4`。

## 安装 fpk

1. 根据飞牛设备的 CPU 架构，选择本地构建的 `dist/easynvr-merger-1.0.4-x86.fpk` 或 `dist/easynvr-merger-1.0.4-arm.fpk`。仓库只保存源码和打包脚本；如未取得安装包，请按下文“从源码重新打包”生成。在飞牛“应用中心”的手动安装功能中选择对应文件。应用声明依赖 `python312`，fnOS 应安装此运行时。已安装旧版本的用户可升级到 1.0.4；升级后请刷新应用页面。
2. 在应用设置中**授权包含录像与输出目录的同一个父目录**。例如把 `/vol1/EasyNVR` 授权给此应用，并确保该目录下存在 `recordings` 和 `output` 两个子目录。应用以专用包用户运行，录像目录需要读权限，输出目录需要写权限。授权变化后如页面仍显示旧目录，请在应用中心重启应用。
3. 从飞牛桌面打开“EasyNVR 录像合并”。在执行计划页面填写 NAS 上的**真实绝对路径**，例如录像目录 `/vol1/EasyNVR/recordings`、输出目录 `/vol1/EasyNVR/output`。两者必须位于已授权父目录内，且不能互相包含。
4. 保存配置，点击“立即执行一次”，在“任务与日志”中核对结果。确认录像合并正确后，再启用定时执行。

fpk 通过飞牛统一网关和本地 Unix Socket 提供页面，**不需要端口映射**。入口只向管理员显示，API 也检查飞牛网关转发的管理员身份。执行计划、去重清单和错误事件保存在 fnOS 应用的持久数据目录 `TRIM_PKGVAR`（SQLite 文件 `easynvr-merge.sqlite3`）；服务日志是同目录的 `service.log`。更新应用时请保留该目录。卸载前如需保留记录，请自行备份。

页面会自动处理写入操作的防跨站令牌，无需手动配置。在“任务与日志”点击“清空日志”，可清除执行记录、详细事件日志和 `service.log`，同时压缩 SQLite 数据库以回收空间。成功或失败的合并任务记录及源文件去重清单会保留，避免重复合并；录像及合并视频不会删除。执行任务期间暂不允许清空。`service.log` 超过 10 MiB 时也会自动清空。

## 合并规则

- 默认按文件名排序；如果录像文件名不能反映录制顺序，可以改为按修改时间排序。只扫描日期目录直属的 `.mp4` 或 `.ts` 文件。
- 同一天不同设备或通道共用日期输出目录，使用递增的 `VideoN.mp4` 编号。后补的历史片段会分配新编号。
- 成功任务持久化保存源文件路径、输出路径和执行日志。再次扫描会跳过已成功处理的源文件，即使手工删除输出文件也不会重复合并。
- 失败任务留下 FFmpeg 错误信息，并在下次运行时重试。输出先写临时文件，验证后发布；已有目标文件不会被覆盖。
- FFmpeg concat 使用 `-c copy`，不重新编码，因此同组源片段的视频、音频参数需要兼容。应用包中包含对应架构的 FFmpeg 可执行文件。
- 执行计划按飞牛设备本地时间每天运行一次，默认时间 01:15，默认关闭。升级前的计划会保留原先设置的小时和分钟，改为每天运行一次。关机期间错过的执行点不会补跑，可手动执行。

## 从源码重新打包

安装飞牛[官方 fnpack 1.2.3](https://developer.fnnas.com/docs/cli/fnpack/) 和 Python 3 后运行：

```sh
python3 build_fpk.py x86 arm
```

构建脚本从 PyPI 下载 `imageio-ffmpeg 0.6.0` 的两个 Linux 轮包，校验固定 SHA-256 后抽取 FFmpeg，调用 `fnpack build`，产物写入 `dist/`。可用 `FNPACK_BIN=/path/to/fnpack` 指定打包工具，`WHEEL_DIR=/path/to/cache` 使用已有轮包。FFmpeg 来源和许可证见包内 `app/licenses/`，以及 [imageio-ffmpeg 项目页](https://pypi.org/project/imageio-ffmpeg/)。

本地逻辑和网关测试：

```sh
python3 -m unittest discover -s tests -v
```

已用官方 `fnpack` 构建并检查两个包的结构。**还需要在实际飞牛设备上验证安装、运行时依赖、目录授权、网关访问、真实录像合并及升级。**

原来的 Docker 文件仍保留在仓库中作为备用部署方式；使用 fpk 时不需要 `.env`、Compose 或 Docker。
