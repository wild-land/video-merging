# 录像合并与加密归档（飞牛 fnOS 原生应用）

应用扫描 EasyNVR 的 `设备/通道/YYYYMMDD` 日期目录，每 60 段（可配置）合并成一个 MP4，最后不足一组也会处理。只扫描今天以前的日期目录。合并视频随后写成同一输出目录下的 `VideoN.mp4.7z`，使用 7z AES-256 加密视频内容，压缩包内的 `VideoN.mp4` 文件名可见。归档校验成功后删除合并视频；本次执行结束后，只清理已成功归档任务记录中的原始片段。这里的“删除”是文件系统删除，不保证清除 NAS 快照、备份或存储介质上的残留数据。

## 安装 fpk

1. 根据飞牛设备的 CPU 架构构建或选择 `dist/easynvr-merger-1.1.0-x86.fpk`、`dist/easynvr-merger-1.1.0-arm.fpk`。仓库保存源码和打包脚本。应用依赖 `python312` 运行时。
2. 在应用设置中授权包含录像与输出目录的父目录，例如 `/vol1/EasyNVR`。录像目录需要读取及删除权限，输出目录需要写权限。授权变化后如页面仍显示旧目录，请重启应用。
3. 在“执行计划”填写 NAS 上的真实绝对路径。录像与输出目录必须分开，不能互相包含。设置压缩密码后先手动执行并检查生成的 `.7z` 文件可以解压，再启用定时执行。

fpk 通过飞牛统一网关和本地 Unix Socket 提供页面，无需端口映射。入口只向管理员显示，API 也检查管理员身份。执行计划、去重记录和错误事件保存在 `TRIM_PKGVAR/easynvr-merge.sqlite3`，服务日志在同目录的 `service.log`。压缩密码单独存于该目录下权限为 `0600` 的 `archive-password` 文件；API 只返回是否已设置密码，页面显示星号占位，不返回原文。应用需要在无人值守的定时任务中读取密码，因此 NAS 管理员及应用进程仍可能取得密码。更改密码不会重新加密以前生成的压缩包。

压缩密码至少 8 位，必须包含大写字母、小写字母、数字和符号。为防止压缩包被下载后离线猜测，实际使用时建议采用至少 15 位的独立随机密码，并在密码管理器中保存。密码丢失后应用无法恢复压缩包内容。

## 处理与失败恢复

- 默认按文件名排序；也可按修改时间排序。只扫描日期目录直属的 `.mp4` 或 `.ts` 文件。同一天不同设备或通道共用日期输出目录，按 `VideoN` 递增编号；后补片段会分配新编号。
- FFmpeg 使用 concat 和 `-c copy`，同组源片段的视频、音频参数需要兼容。合并后的 MP4 会先校验，再压缩、加密、测试归档。任务仅在归档测试成功后标记成功；已有目标文件不会被覆盖。
- 如果合并、加密、校验或明文删除失败，相关原片会保留并等待下次重试。任务结束时，对归档散列值及原片大小、修改时间、设备号和 inode 再次核对，只删除完全匹配的原片。删除失败会留在记录中并在下次执行时重试。
- 压缩前的明文视频会短暂存在输出目录。压缩包发布后，应用会删除该明文文件；存储空间必须足以容纳处理期间的明文和压缩包。MP4 通常已压缩，7z 带来的空间节省可能很少。
- 升级前已标记成功的旧版 MP4 任务不会自动压缩或删除原片，避免在没有重新验证的情况下批量清理旧录像。升级前正在失败或中断状态的任务会按新流程重试。
- 执行计划按设备本地时间每天运行一次，默认 01:15、默认关闭。错过执行时间不会补跑，可手动执行。

“清空日志”只清除执行记录、事件和服务日志，并压缩 SQLite 数据库；成功任务与原片去重、清理记录仍保留。录像和压缩包不会因此删除。

## 从源码打包和测试

使用官方 `fnpack` 和 Python 3：

```sh
python3 build_fpk.py x86 arm
python3 -m unittest discover -s tests -v
```

构建脚本下载固定版本的 `imageio-ffmpeg` 轮包和官方 7-Zip Linux 可执行文件，并校验 SHA-256；可用 `FNPACK_BIN` 指定 fnpack、`WHEEL_DIR` 指定下载缓存。许可证放入应用包内。仍需在实际飞牛设备上验证安装、目录删除权限、真实录像、压缩与升级。
